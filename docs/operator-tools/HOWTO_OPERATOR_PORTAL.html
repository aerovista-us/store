2. Daily operator loop (safe “don’t publish unless green”)

Run from a terminal at the repo root (d:\\mini.shops\\av_storefront).

  1. Open Catalog Console v1.1:
    • Open AeroVista_Catalog_Console/v1.1/index.html in your browser.
    • Import latest Square export (CSV or JSON).
    • Use Bulk to normalize sizes/colors & apply ladders.
    • Use Validate tab to fix missing descriptions/prices, bad sizes, duplicate SKUs.
  2. Export your updated catalog JSON:
    • Export to the repo root as a review file (for example square_products_edited.json).
    • After review, either replace square_products_latest.json or point STORE_CATALOG_PATH at the exported file before deploy.
  3. Run the pre‑publish gate (single command):
    python backend/scripts/pre_publish_gate.py \
    --catalog square_products_edited.json \
    --overlay storefront_overlay.json
    • Gate runs: data‑quality → profit floor → optional Printful map coverage.
    • Exit code 0 = automated checks green; non‑zero = investigate.
  4. Update Square (when gate is green):
    python backend/scripts/export_square_update_csv.py
    • Opens/creates exports/square_update_from_edited.csv.
    • Open a fresh Square export CSV + this file side‑by‑side.
    • Copy only the fields you intend to update (usually prices + maybe name/description) into the Square CSV, then import via Square Dashboard (start with a 5‑item test).
Square = retail truth Console v1.1 = editor + validator Overlay = presentation layer Printful = cost + fulfillment only

3. Common tasks (copy‑paste ready)

3.1 Run data‑quality only (Square CSV or JSON)

Find missing descriptions/images/prices before editing.

# JSON (live or edited)
python backend/scripts/generate_data_quality_report.py \
--input square_products_latest.json

# Square Items CSV export
python backend/scripts/generate_data_quality_report.py \
--input square_items_export.csv \
--kind csv \
--name-field "Item Name" \
--description-field "Description" \
--image-field "Image URL" \
--price-field "Price"

3.2 Run profit floor check only

Ensures no variant sells below cost + ship buffer + fees.

python backend/scripts/validate_profit_floor.py \
storefront_overlay.json \
square_products_edited.json

3.3 Generate Square Update CSV from edited JSON

Minimal CSV you merge into a fresh Square export.

python backend/scripts/export_square_update_csv.py

Output: exports/square_update_from_edited.csv

3.4 Regenerate Printful exports + variant map (offline)

Used only for fulfillment mapping and cost reference.

# 1) Export from Printful
python backend/scripts/printful_my_products_export.py

# 2) Build Square → Printful variant map
python backend/scripts/build_printful_variant_map.py \
--variants printful_my_variants.csv

Map is written to backend/data/printful_variant_map.json.

3.5 Run full pre‑publish gate with Printful coverage required

python backend/scripts/pre_publish_gate.py \
--catalog square_products_edited.json \
--overlay storefront_overlay.json \
--printful-map backend/data/printful_variant_map.json \
--require-printful-map

Use --require-printful-map only for products that must be dropship‑fulfillable.

4. Role‑based quick recipes

Catalog Curator — Weekly cleanup

  1. Export latest catalog from Square (CSV).
  2. Open Console v1.1, import, run Bulk + Validate.
  3. Mark keeper products in overlay overrides with curated copy + copyLock: true.
  4. Export a review catalog JSON, run pre_publish_gate.py, then make that file the active storefront catalog by replacing square_products_latest.json or using STORE_CATALOG_PATH.
  5. If green, generate Square Update CSV and apply to Square.

Designer / Production — New design

  1. Create product in Printful and publish to Square.
  2. Export Square CSV; import into Console v1.1.
  3. Set collection / productType / color, apply ladders, add copy.
  4. Export review JSON, run gate, then push updates back into Square and/or make that file the active storefront catalog.

Publisher — “Does this look right?”

  1. Ensure the intended active catalog file is ready: usually square_products_latest.json, or an override file referenced by STORE_CATALOG_PATH.
  2. Open index.html and confirm the storefront is loading that exact file.
  3. Use overlay + copyLock to ensure titles/prices/descriptions match house style.
  4. Run gate on the same catalog file before any Square import.

5. Mental model (one sentence)

Square is retail truth; Catalog Console v1.1 edits and validates it; the storefront overlay enforces presentation and copyLock without ever setting checkout prices; Printful exports stay offline as cost + fulfillment map until you deliberately turn on automation.

No runtime changes from this page Never bypass the gate for production

6. Troubleshooting pointers

  • Storefront shows wrong set of products — confirm which file is active: default square_products_latest.json or the path supplied via STORE_CATALOG_PATH.
  • Gate fails on data quality — open data_quality_reports/data_quality_issues.csv; fix missing desc/img/price in Console or Square, then re‑export JSON.
  • Gate fails on profit floor — adjust ladders or rules.costByLadder/rules.shipBufferCents in storefront_overlay.json, then rerun.
  • Pre‑publish gate exits 1 but you missed why — scroll up in the terminal; each failing step prints a line with its exit code and a short reason.
  • Need deeper docs — start from handoffnotes.md and the docs linked in section 1.
