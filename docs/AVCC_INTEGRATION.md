# AVCC integration — AeroVista Command Center ↔ commerce storefronts

**Last updated:** 2026-07-26

## Names (do not confuse)

| Label | What | URL / path |
|-------|------|------------|
| **AVCC** | **AeroVista Command Center** — operator hub (CRM, work orders, calendar, identity, proxies) | https://avcc.aerocoreos.com · repo `aerovista-command-center/` |
| **Catalog Console** | Product catalog cleanup + deploy (this repo) | https://store-console.aerocoreos.com · `aerovista-store/console/` |
| **Shop** | Customer storefront | https://gear.aerovista.us · `aerovista-store/store/` |
| **Horizon** | Aerial-art storefront; public noindex preview, checkout gated | https://horizon.aerovista.us · `aerovista-store/horizon/` |
| **Payment API** | Checkout + fulfillment | https://api.aerovista.us · `aerovista-store/store/backend/` (not in git) |

AVCC is the **parent operator shell**. The catalog console is a **specialized tool** for Square → JSON → shop publish.

## Machine-readable bridge manifest

After `npm run sync:all`, the store repo writes:

**`public/build-source-manifest.json`**

AVCC should read this (from git raw, Collab sync, or a service proxy) to show deploy surface status and deep links.

Example shape (v2):

```json
{
  "name": "AV Store Static Bridge",
  "version": 2,
  "commandCenter": {
    "name": "AeroVista Command Center",
    "abbrev": "AVCC",
    "url": "https://avcc.aerocoreos.com",
    "repo": "aerovista-command-center"
  },
  "services": {
    "shop": { "url": "https://gear.aerovista.us", "deploy": "GitHub Pages" },
    "catalogConsole": { "url": "https://store-console.aerocoreos.com", "deploy": "NXCore Docker" },
    "paymentApi": { "url": "https://api.aerovista.us", "deploy": "NXCore SSH" }
  },
  "store": { "enabled": true, "source": "store", "output": "public/shop", "pagesDomain": "gear.aerovista.us" },
  "console": { "enabled": true, "source": "console", "output": "public/console" },
  "generatedAt": "2026-06-14T…"
}
```

Regenerated by: `scripts/write-build-source-manifest.mjs` (part of `sync:all` / `deploy:server`).

The current manifest is Gear-centric. Do not report Horizon as deployed or
healthy from this manifest. Add Horizon release evidence only after a
sanitized artifact has been created and an isolated preview exists; follow
[`horizon/DEPLOYMENT_SOP.md`](../horizon/DEPLOYMENT_SOP.md).

## Catalog console APIs (for AVCC proxies)

When AVCC proxies to the hosted catalog console (`store-console`), these routes exist on **`console/server.js`**:

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/health` | Console up, store mount writable |
| GET | `/api/bridge/manifest` | Same as legacy `/api/avcc/manifest` |
| GET | `/api/store/catalog-meta` | On-disk catalog mtime / count |
| GET | `/api/store/images` | Filenames in `store/img/` |
| GET | `/api/proxy/bootstrap` | Payment API sellable cart keys |
| POST | `/api/deploy` | Write `square_products_latest.json` (+ overlay) |

AVCC identity authority should gate access to store-console and ops API routes.

## Catalog contract (shared JSON)

Both catalog console and AVCC automations must preserve:

**`store/square_products_latest.json`**

- `products[].variants[].variation_id` — Square Token (required for checkout)
- `products[].collection` — home lane grouping
- Cart key at checkout: `{ColorOrDefault}__{Size}`

Deploy paths:

1. **Catalog console** → `POST /api/deploy` (NXCore) or `npm run deploy:server` (local)
2. **AVCC automation** → write same JSON path + trigger git push / NXCore copy (implement in `aerovista-command-center`)

These paths are Gear-only. Horizon uses `horizon/catalog.json` and must never
be sent through the Gear publisher.
